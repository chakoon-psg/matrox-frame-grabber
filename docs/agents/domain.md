# 도메인 문서

엔지니어링 스킬들이 이 리포를 탐색할 때 도메인 문서를 어떻게 참고해야 하는지 정한다.

이 리포는 **단일 컨텍스트**다 — 루트에 `CONTEXT.md` 하나, `docs/adr/` 하나.

## 탐색 전에 읽을 것

- 리포 루트의 **`CONTEXT.md`**
- **`docs/adr/`** — 지금 작업하려는 영역과 관련된 ADR을 읽는다.

이 파일들이 없으면 **아무 말 없이 그냥 진행한다.** 없다고 지적하지 말고, 미리 만들자고 제안하지도
않는다. 용어나 결정이 실제로 확정되는 시점에 `/domain-modeling` 스킬이 그때그때 만든다.
(`/grill-with-docs`와 `/improve-codebase-architecture`를 통해 호출된다.)

## 파일 구조

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── src/
```

나중에 여러 패키지로 나뉘면 루트에 `CONTEXT-MAP.md`를 두고 컨텍스트마다 `CONTEXT.md`를 가리키게
바꾼다. 컨텍스트별 ADR은 `src/<컨텍스트>/docs/adr/`에 둔다. 그때 `/setup-matt-pocock-skills`를
다시 실행한다.

## 글로서리의 어휘를 쓴다

출력물에서 도메인 개념을 지칭할 때(이슈 제목, 리팩터링 제안, 가설, 테스트 이름) `CONTEXT.md`에
정의된 용어를 그대로 쓴다. 글로서리가 명시적으로 피하라고 한 동의어로 흘러가지 않는다.

필요한 개념이 아직 글로서리에 없다면 그것 자체가 신호다 — 프로젝트가 쓰지 않는 말을 지어내고
있거나(재고할 것), 진짜 빈틈이 있는 것이다(`/domain-modeling`에 넘길 것).

## ADR과 충돌하면 드러낸다

출력물이 기존 ADR과 어긋나면 조용히 덮어쓰지 말고 명시적으로 밝힌다.
