# 인코딩은 전부 ffmpeg로 하고 MIL을 쓰지 않는다

두 녹화 모드 모두 MIL의 시퀀스·압축 모듈이 아니라 외부 `ffmpeg` 프로세스에 프레임을 흘려보내
영상을 만든다. 취향의 문제가 아니다 — 이 장비의 MIL 라이선스는 압축을 전혀 허용하지 않고
보드에도 자체 인코더가 없어서, 영상 파일을 만들 방법이 ffmpeg뿐이었다.

## 검토한 대안

- **MIL `Mseq` 압축 시퀀스** — 기각. `MseqAlloc`이 라이선스 오류로 실패한다.
  `MappInquire(M_LICENSE_MODULES)`와 `M_LICENSE_VALID_MODULES`가 모두 `0x1`
  (`M_LICENSE_LITE`, 기본 grab·display만)을 반환한다. JPEGSTD와 JPEG2000 모듈 플래그가 없고
  처리 모듈도 전부 없다.
- **보드 내장 H.264 인코딩** — 기각. `MsysInquire(M_BOARD_TYPE)`의 `M_H264` 비트가 0이다.
  이 보드에는 하드웨어 인코더가 없다.
- **MIL 압축 라이선스 구매** — 산다고 해도 기각. MIL을 통한 MJPEG는 디베이어된 컬러 프레임을
  기록하는데, 이는 Bayer mosaic보다 세 배 크고 원본 프레임레이트에서 호스트 전송 대역에 맞지
  않는다. 즉 ffmpeg 경로에서는 잃지 않을 프레임을 잃게 된다.

## 결과

ffmpeg는 패키지 참조가 아니라 **런타임 의존성**이다. 앱이 시작할 때 위치를 찾고, 찾지 못하면
두 녹화 모드가 비활성화되며 라이브 뷰는 계속 동작한다. 녹화 가능 여부를 가르는 것은 **오직 이
탐색 결과뿐**이며, 녹화 경로 어디에서도 MIL 라이선스를 확인하지 않는다.
